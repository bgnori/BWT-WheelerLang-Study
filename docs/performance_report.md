# FM-index 性能測定レポート

## 概要

本レポートは、FM-index の以下2つの指標を3種のデータセット・3種のアルゴリズムで比較測定した結果をまとめたものです。

- **インデックス構築コスト** — テキストから FM-index (または suffix array) を構築するまでの時間・メモリ
- **検索コスト** — 構築済みインデックスに対して完全一致パターンおよび star-free 正規表現で検索するときの時間・メモリ

## 測定環境

| 項目 | 値 |
|------|---|
| CPU | Intel Xeon 6973P-C |
| OS | Linux (amd64) |
| Go | 1.21 |
| ベンチマーク時間 | -benchtime=3s |
| GOMAXPROCS | 4 |

ベンチマークは `go test -bench=. -benchmem -benchtime=3s .` で実行しました。
ソースコードは [`bench_test.go`](../bench_test.go) を参照してください。

## 1. インデックス構築コスト

3種のアルゴリズムを比較します。

| 略称 | 正式名称 | 計算量 | 実装 |
|------|----------|--------|------|
| **Doubling** | Prefix Doubling (Manber-Myers) | O(*n* log² *n*) | `AlgorithmDoubling` — 本プロジェクト内 `fmindex` パッケージ |
| **SA-IS** | Suffix Array Induced Sorting | O(*n*) | `AlgorithmSAIS` — 本プロジェクト内 `fmindex` パッケージ |
| **Stdlib** | Go 標準ライブラリ `index/suffixarray` | O(*n*) | `suffixarray.New()` — BWT/Occ ビット列なし、SA のみ |

> SA-IS と Stdlib はどちらも線形時間ですが、**Stdlib は FM-index の BWT・Occ ビット列を構築しない**ため、構築コストが低くなります。FM-index を持たない Stdlib では後述の正規表現検索は不可能です。

### Moby Dick (1.2 MB)

| アルゴリズム | 実行時間 (ns/op) | スループット (MB/s) | メモリ (B/op) | allocs/op |
|------------|----------------|-------------------|--------------|-----------|
| Doubling   | 530,567,890 (530 ms) | 2.26 | 51,855,410 (49 MB) | 161 |
| SA-IS      | 82,347,878 (82 ms) | 14.57 | 111,421,152 (106 MB) | 328 |
| Stdlib     | 39,039,502 (39 ms) | 30.74 | 4,800,596 (4.6 MB) | 2 |

### 上杉謙信 / Kenshin (400 KB)

| アルゴリズム | 実行時間 (ns/op) | スループット (MB/s) | メモリ (B/op) | allocs/op |
|------------|----------------|-------------------|--------------|-----------|
| Doubling   | 152,147,103 (152 ms) | 2.63 | 20,112,686 (19 MB) | 221 |
| SA-IS      | 22,753,545 (23 ms) | 17.58 | 39,294,176 (37 MB) | 369 |
| Stdlib     | 10,618,651 (11 ms) | 37.67 | 1,884,247 (1.8 MB) | 3 |

### Git ソース (4.7 MB)

| アルゴリズム | 実行時間 (ns/op) | スループット (MB/s) | メモリ (B/op) | allocs/op |
|------------|----------------|-------------------|--------------|-----------|
| Doubling   | 3,542,324,436 (3.5 s) | 1.39 | 213,795,232 (204 MB) | 175 |
| SA-IS      | 419,038,290 (419 ms) | 11.73 | 440,890,526 (420 MB) | 404 |
| Stdlib     | 149,441,946 (149 ms) | 32.88 | 19,660,884 (19 MB) | 2 |

### 構築速度の比較 (倍率)

| 比較ペア | Moby Dick | Kenshin | Git |
|----------|-----------|---------|-----|
| Doubling / SA-IS | **6.4×** | **6.7×** | **8.5×** |
| Doubling / Stdlib | **13.6×** | **14.3×** | **23.7×** |
| SA-IS / Stdlib | **2.1×** | **2.1×** | **2.8×** |

### 構築コストの考察

1. **Doubling は最も低速** — O(*n* log² *n*) の計算量が顕著に現れており、データサイズが大きくなると差が拡大します（Git で Doubling/SA-IS 比が 8.5×）。
2. **SA-IS は Stdlib の約 2–3× 遅い** — 両者とも線形時間ですが、FM-index は SA に加えて BWT・Occ ビット列・C 配列を追加構築するためオーバーヘッドが生じます。
3. **メモリ使用量** — SA-IS は Doubling より多くのメモリを消費します。SA-IS アルゴリズム内部で使用する補助配列（LMS 分類・名前付け用）が原因です。Stdlib は SA のみを保持するため最も省メモリです。
4. **FM-index の構築コストは投資** — Stdlib は構築は速いものの、後述のように検索は FM-index に大きく劣ります。

## 2. 完全一致検索コスト

インデックスは事前構築済み（構築時間は測定対象外）。`Count(pattern)` / `Lookup(pattern, -1)` のみを計測します。

| 手法 | 計算量 | アロケーション |
|------|--------|----------------|
| FM-index `Count` | O(\|P\|) — パターン長のみ | 0 bytes（ゼロアロケーション） |
| Stdlib `Lookup` | O(\|P\| log *n*) — テキスト長に依存 | 結果スライス分を毎回アロケーション |

### Moby Dick — 完全一致検索

| パターン | ヒット数 | FM-index (ns/op) | Stdlib (ns/op) | FM/Stdlib 比 | Stdlib B/op |
|----------|---------|-----------------|----------------|-------------|------------|
| `the` | 3,426 | **19.85** | 2,684 | **135×** | 28,672 |
| `whale` | 14,332 | **33.24** | 10,331 | **311×** | 114,688 |
| `white whale` | 3,385 | **74.16** | 2,550 | **34×** | 27,264 |
| `captain` | 3,327 | **50.90** | 2,545 | **50×** | 27,264 |
| `Ahab` | 3,583 | **28.74** | 2,780 | **97×** | 28,672 |

### 上杉謙信 / Kenshin — 完全一致検索

| パターン | ヒット数 | FM-index (ns/op) | Stdlib (ns/op) | FM/Stdlib 比 | Stdlib B/op |
|----------|---------|-----------------|----------------|-------------|------------|
| `謙信` | 1,981 | **39.98** | 2,169 | **54×** | 16,384 |
| `上杉謙信` | 1,002 | **82.72** | 1,197 | **14×** | 8,192 |
| `武田信玄` | 1,040 | **81.29** | 1,003 | **12×** | 9,472 |
| `戦国` | 1,001 | **46.09** | 1,238 | **27×** | 8,192 |
| `越後` | 981 | **42.29** | 1,207 | **29×** | 8,192 |

### Git ソース — 完全一致検索

| パターン | ヒット数 | FM-index (ns/op) | Stdlib (ns/op) | FM/Stdlib 比 | Stdlib B/op |
|----------|---------|-----------------|----------------|-------------|------------|
| `struct` | 13,841 | **40.00** | 10,002 | **250×** | 114,688 |
| `commit` | 10,305 | **40.00** | 8,017 | **200×** | 90,112 |
| `#include` | 7,390 | **54.53** | 5,718 | **105×** | 65,536 |
| `malloc` | 5,637 | **38.70** | 4,639 | **120×** | 49,152 |
| `diff` | 10,389 | **25.86** | 7,917 | **306×** | 90,112 |

### 検索コストの考察

1. **FM-index は圧倒的に高速** — 全パターンで FM-index が Stdlib を大幅に上回ります（12×〜311× 高速）。
2. **ヒット数が多いほど差が拡大** — Stdlib は結果スライスをヒット数に比例してアロケーションしますが、FM-index の `Count` は SA 区間の長さを返すだけでゼロアロケーションです。`whale`（14,332 ヒット）で Stdlib は 114 KB をアロケーションするのに対し FM-index は 0 bytes です。
3. **FM-index の検索時間はパターン長のみに依存** — `whale`（5 文字）は `the`（3 文字）より遅く、`white whale`（11 文字）はさらに遅いという O(\|P\|) の挙動が確認できます。UTF-8 日本語では `謙信`（6 バイト）より `上杉謙信`（12 バイト）が遅くなっています。
4. **構築アルゴリズム（Doubling / SA-IS）は検索速度に影響しない** — どちらも同一の FM-index 構造を生成するため、構築後の検索性能は同等です。

## 3. Star-free 正規表現検索コスト

FM-index のみが star-free 正規表現に対応しています。Go 標準ライブラリの `index/suffixarray` は正規表現をサポートしないため比較対象から除外します。

> **Star-free 正規表現**とは、Kleene star (`*`) や one-or-more (`+`) の無限繰り返しを含まない正規表現です。交替 (`|`)・文字クラス (`[...]`)・連結・任意 (`?`)・有界繰り返し (`{n,m}`) は使用可能です。

### Moby Dick — 正規表現検索

| パターン | ヒット数 | ns/op | B/op | allocs/op |
|----------|---------|-------|------|-----------|
| `whale\|ship` | 17,790 | 2,134 | 2,352 | 57 |
| `[Ww]hale` | 14,594 | 1,564 | 2,072 | 51 |
| `captain\|Ahab\|Ishmael` | 10,499 | 3,237 | 3,392 | 89 |

### 上杉謙信 / Kenshin — 正規表現検索

| パターン | ヒット数 | ns/op | B/op | allocs/op |
|----------|---------|-------|------|-----------|
| `上杉謙信\|武田信玄` | 2,042 | 2,759 | 2,920 | 87 |
| `謙信\|信玄` | 4,007 | 1,772 | 2,120 | 55 |
| `越後\|越前` | 1,993 | 1,351 | 1,968 | 33 |

### Git ソース — 正規表現検索

| パターン | ヒット数 | ns/op | B/op | allocs/op |
|----------|---------|-------|------|-----------|
| `commit\|diff` | 20,694 | 2,055 | 2,392 | 59 |
| `#include\|#define` | 7,390 | 3,111 | 2,960 | 74 |
| `malloc\|free` | 11,152 | 2,133 | 2,392 | 59 |

### 正規表現検索の考察

1. **正規表現検索は完全一致の約 20〜100 倍遅い** — 完全一致 Count が 20〜80 ns であるのに対し、正規表現検索は 1,351〜3,237 ns（約 1.4〜3.2 μs）です。これは主に「正規表現の構文解析・評価・区間のマージ処理」のオーバーヘッドによるものです。
2. **交替数が多いほど遅い** — `captain|Ahab|Ishmael`（3 択）は `whale|ship`（2 択）より約 1.5× 遅くなっています。各交替枝についてバックワード探索が走るためです。
3. **文字クラス `[Ww]hale` は交替と同程度** — 内部的に 2 文字を並列探索するため、`whale|ship` と同程度の速度です。
4. **アロケーション数はパターンの複雑度に比例** — `allocs/op` は区間リスト（`[]Interval`）の生成回数に対応し、交替枝が多いほど増加します。
5. **ヒット数との関係** — 正規表現検索はヒット数に関係なく SA 区間だけを返すため（`limit=0` で全件）、メモリは区間リストのみです。ヒット数が非常に多い場合でも大量アロケーションは発生しません。

## 総合比較

### 構築速度

```
高速 ←────────────────────────────────────────→ 低速
  Stdlib      SA-IS            Doubling
  (SA only)  (FM-index O(n))  (FM-index O(n log²n))
     1×          2–3×              14–24×
```

### 検索速度（完全一致、FM-index が速い）

```
高速 ←──────────────────────────────────→ 低速
  FM-index Count   Stdlib Lookup
     O(|P|)         O(|P| log n) + アロケーション
      1×              12–311×
```

### 機能比較

| 機能 | Doubling (FM) | SA-IS (FM) | Stdlib |
|------|:---:|:---:|:---:|
| 完全一致検索 | ✓ | ✓ | ✓ |
| Star-free 正規表現検索 | ✓ | ✓ | ✗ |
| ゼロアロケーション検索 | ✓ | ✓ | ✗ |
| 省メモリ構築 | △ | ✗ | ✓ |
| 高速構築 | ✗ | △ | ✓ |

## まとめと推奨事項

| 用途 | 推奨アルゴリズム | 理由 |
|------|----------------|------|
| 大規模テキストへの繰り返し検索 | **SA-IS (FM-index)** | 構築は中程度の速さ・検索は圧倒的に高速 |
| 正規表現検索が必要 | **SA-IS (FM-index)** | Stdlib は正規表現非対応 |
| 小規模テキスト・検索頻度が低い | **Stdlib** | 構築が速くメモリが少ない |
| メモリ制約が厳しい | **Stdlib** | SA のみを保持し省メモリ |
| Doubling の用途 | ほぼなし | SA-IS より遅く、Stdlib より遅い。学習・理解目的に限定 |

**結論**: FM-index（SA-IS アルゴリズム）は構築コストが Stdlib の約 2–3 倍かかる一方で、検索速度は 12×〜311× 高速でゼロアロケーションです。検索が繰り返されるアプリケーションでは FM-index の投資対効果は非常に高く、正規表現検索が必要な場面では唯一の選択肢となります。
